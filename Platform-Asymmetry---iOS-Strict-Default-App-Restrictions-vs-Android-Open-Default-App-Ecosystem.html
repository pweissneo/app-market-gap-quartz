Platform Asymmetry - iOS Strict Default App Restrictions vs Android Open Default App Ecosystem

iOS allows users to change exactly two defaults: web browser and email client. Every other default — dialer, SMS, maps, music, call screening, password manager — is locked to Apple’s choice. Android allows users to set default apps for virtually any app category, including dialer, SMS, maps, music, home assistant, and browser. This asymmetry determines which apps can become the entry point for whole categories of user behavior, and therefore which apps can build the engagement and data flywheels that define category leaders.

iOS: Two Defaults, Everything Else Locked

Apple’s philosophy: defaults are part of the product experience, and changing them undermines the integrated experience. iOS allows changing:

  1. Default browser (iOS 14+, 2020)
  2. Default email client (iOS 14+, 2020)

Everything else is fixed. The lock extends to Siri integration: only Apple Music can be invoked via Siri voice command for music playback. Third-party music apps must be explicitly opened; Siri cannot play songs from Spotify or YouTube Music via voice.

The Mechanism

Apple enforces default locks through:

  • SiriKit Intents: Third-party apps cannot register Siri shortcuts for most intent types; only Apple-built apps can handle certain intents natively
  • Extension points: iOS allows some extensions (keyboard, share sheet, content blockers) but the system UI behavior remains Apple’s
  • CarPlay: Third-party car apps have limited CarPlay support; mapping and music are Apple-dominated
  • HomeKit: Only HomeKit-certified devices can integrate deeply with the Home app; Matter devices have interoperability but native Home app experience is Apple-designed

The User Experience Cost

iOS users who prefer third-party alternatives face friction at every interaction:

  • Every URL link opens Safari (even if Chrome is set as default browser, links in apps often still open Safari)
  • “Send a message” Siri command sends via iMessage, not WhatsApp or Signal
  • “Navigate to” Siri command opens Apple Maps, not Google Maps or Waze
  • Apple Maps is the only maps app with deep Siri and CarPlay integration
  • iCloud Keychain is the only password manager that autofills in Safari and App Store without extra steps

The Developer Cost

For iOS developers, the default lock means:

  • Even if users prefer their app, every voice command, universal link, or deep link from the OS will route to Apple’s app
  • A better navigation app cannot become the default maps app — it will always be a secondary option users must open manually
  • A privacy-focused messaging app cannot become the default SMS app — iMessage is always the primary
  • Building a password manager on iOS requires users to manually enable it in Settings; iCloud Keychain is pre-enabled

Android: Open Default for (Almost) Everything

Android’s approach: the OS is a platform, not a product. Users should be able to choose their default for any category. Android allows:

  • Setting any compatible app as default for any category via Settings → Apps → Default apps
  • Apps declaring intent-filters for specific URI schemes, MIME types, or activities
  • The ability to clear defaults and re-prompt via “Open by default” settings

The Mechanism

Android enforces defaults through:

  • Intent resolution: When an intent is fired (e.g., ACTION_VIEW for a URL), the system offers a choice of apps or launches the user-selected default
  • Preferred activities: Apps can set preferred activities via PackageManager
  • OEM variations: Samsung, Pixel, and other OEMs add their own default app settings, sometimes overriding AOSP behavior

The Fragmentation Cost

The open default model creates its own problems:

  • Users may not know they can change defaults, or may be overwhelmed by the choice
  • Different Android OEMs pre-install and pre-default their own apps (Samsung sets Samsung Internet, Samsung Messages, Samsung Maps, etc.)
  • The “choose default app” prompt appears frequently, which can be confusing for non-technical users
  • OEMs lock defaults too — Samsung Galaxy devices lock some defaults to Samsung apps in ways that are harder to change than pure AOSP Android

Why This Matters: The Default App Flywheel

The default app controls the entry point to whole categories of behavior, and the entry point controls the data flywheel:

Default app → Entry point → Daily usage → Behavioral data →
Better product → More users → More data → Tighter integration →
Harder to dislodge

Maps example:

  • iOS: Apple Maps is the default. Every “navigate to” from Safari, Siri, Calendar, and Contacts opens Apple Maps. Apple collects driving data from millions of iOS users. Third-party maps apps (Google Maps, Waze) must be explicitly opened and never collect this ambient navigation data.
  • Android: Google Maps is often the default on Pixel, but Samsung sets Samsung Maps as default on Galaxy devices. Users on any Android device can switch to Google Maps, Waze, or any other option. Navigation data is split across multiple apps.

Messaging example:

  • iOS: iMessage is the default and deeply integrated. “Message” from any context sends iMessage. Blue bubbles, Animoji, and FaceTime video calls are iMessage features. WhatsApp, Signal, and Telegram must be explicitly opened.
  • Android: Google Messages is the default on Pixel; Samsung Messages on Galaxy; users can switch to WhatsApp, Signal, or any messaging app as default. The messaging market on Android is genuinely competitive.

Dialer/Phone example:

  • iOS: Apple Phone app is the only option. CallKit allows third-party VoIP apps to integrate with the phone UI, but the native dialer is always Apple’s.
  • Android: Google Phone (Pixel), Samsung Phone (Galaxy), OnePlus Phone, and OEM variants are all separate defaults. Truecaller and other call-screening apps integrate with the phone app on both platforms, but the dialer itself is interchangeable on Android.

The Specific Gap: Third-Party Call Screening

One of the most consequential default locks is call screening:

  • iOS: Apple Call Screen (built into iOS 13+) is the default call screening solution. Third-party call screening apps (Truecaller, Hiya) cannot become the default handler for incoming calls. They can provide identification but cannot block calls at the system level without using CallKit, which has limitations.
  • Android: Google Phone (on Pixel) and Samsung Phone (on Galaxy) offer built-in screening, but users can replace the dialer entirely with Truecaller or other apps that provide system-level call blocking. Truecaller has over 150 million users on Android specifically because it can become the default dialer.

The asymmetry: Truecaller is the dominant caller ID and spam-blocking app globally. On Android, it thrives because it can be the default dialer. On iOS, it is a secondary app that requires manual intervention for every call — fundamentally limiting its utility.

The EU Regulatory Angle

The EU’s Digital Markets Act (DMA) has not yet targeted default app restrictions on iOS in the same way it targeted browser engines and alternative payments. Apple’s compliance has focused on:

  • Alternative app stores
  • Third-party payment processors
  • Browser engine choice

Default app restrictions remain largely unaddressed. This creates a regulatory asymmetry: EU iOS users still cannot set default maps, music, or messaging apps despite benefiting from alternative stores and payment options.

Potential DMA expansion: If the DMA is amended or interpreted to cover default app locks, iOS could be forced to allow default app selection for maps, music, and messaging in the EU — similar to how the browser engine ruling forced Apple to open Safari’s rendering engine. No such ruling exists as of September 2026.
